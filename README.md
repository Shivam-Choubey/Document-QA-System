# Document Q&A System

A beginner-friendly, fully local **RAG (Retrieval-Augmented Generation)** project. Upload your own PDFs, ask questions about them in plain English, and get answers generated by a local AI model — no OpenAI, Gemini, or paid API required.

This project is built to be a **learning resource**. The code is intentionally simple and heavily commented so that if you come back to it in six months, you can re-read it and remember exactly how RAG works.

---

## About the Project

Large Language Models (LLMs) are great at writing text, but they don't know anything about *your* private documents — they only know what they were trained on. RAG solves this by:

1. Searching your documents for the parts relevant to your question.
2. Handing that relevant text to the LLM as extra context.
3. Letting the LLM write an answer *grounded* in your actual documents, instead of guessing from memory.

This project implements that exact idea from scratch, using small models that can run on a normal laptop.

## What is RAG?

**RAG = Retrieval-Augmented Generation.**

- **Retrieval** — given a question, find the most relevant pieces of text from a knowledge base (here, your PDFs).
- **Augmented** — those pieces of text are added ("augmented") into the prompt sent to the LLM.
- **Generation** — the LLM generates a natural-language answer using that provided text.

In short: *instead of asking an LLM "what do you know about X?", RAG asks "here is some real information about X — now answer this question using it."*

## How This Project Works

```text
PDF
 ↓
Text Extraction        (PyMuPDF pulls plain text out of the PDF)
 ↓
Chunking                (text is split into small overlapping pieces)
 ↓
Sentence Transformer    (each chunk is converted into a numeric vector)
 ↓
Embeddings
 ↓
ChromaDB                (chunks + vectors + metadata are stored on disk)
 ↓
Retriever               (your question is embedded and compared against
 ↓                        every stored chunk to find the closest matches)
Relevant Context
 ↓
Local Transformer LLM   (context + question are turned into a prompt and
 ↓                        fed to a small local generative model)
Answer
```

There are two *different* AI models used here — it's easy to mix them up:

| Model | Type | Job |
|---|---|---|
| `all-MiniLM-L6-v2` | Sentence Transformer | Converts text into vectors so we can **search** for similar meaning |
| `flan-t5-base` | Generative LLM | Reads context + question and **writes** an answer |

## Architecture

```text
Document-QA-System/
│
├── data/                  # (optional) place to keep sample PDFs
│
├── ingestion/
│   └── ingestion.py       # Load PDFs → chunk → embed → store in ChromaDB
│
├── retrieval/
│   └── retriever.py       # Embed the question → search ChromaDB → top-k chunks
│
├── generation/
│   └── generator.py       # Build prompt → run local LLM → return answer
│
├── chroma_db/             # ChromaDB's persistent on-disk storage (auto-created)
│
├── app/
│   └── main.py            # Streamlit UI that wires everything together
│
├── requirements.txt
├── .env
└── README.md
```

## Tech Stack

- **Streamlit** — web UI
- **PyMuPDF (fitz)** — PDF text extraction
- **sentence-transformers** — local embedding model
- **ChromaDB** — local, persistent vector database
- **transformers + torch** — local generative LLM (Hugging Face)

Everything runs on your own machine. No API keys, no per-request cost.

## Project Structure

See [Architecture](#architecture) above — each folder has exactly one responsibility, which makes the codebase easy to navigate and extend later.


## Installation

### Create Virtual Environment

**Windows:**
```bash
python -m venv venv
```



### Activate Virtual Environment

**Windows:**
```bash
venv\Scripts\activate
```

### Install Dependencies

```bash
pip install -r requirements.txt
```

The first time you run the app, `sentence-transformers` and `transformers` will automatically download the required models (a few hundred MB to ~1 GB total). This only happens once — after that, the models are cached locally.

## Add Documents

Either:
- Drop PDF files into the `data/` folder for your own reference, **or**
- Simply upload PDFs directly through the Streamlit UI's file uploader (this is the primary way to use the app).

## Run the Application

```bash
streamlit run app/main.py
```


## Future Improvements

These are intentionally **not** implemented in this beginner version, to keep the codebase simple and focused on core RAG concepts:

- Better/smarter chunking strategies
- Hybrid search (keyword + semantic)
- Reranking retrieved results
- Query rewriting
- Conversation memory (multi-turn chat)
- RAG evaluation metrics
- FastAPI backend
- Docker packaging
- Cloud deployment
- Azure AI Search integration
- OpenAI/Gemini integration for higher-quality generation
